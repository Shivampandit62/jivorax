How to use this encoder

  1. Type or paste your text. The encoded output updates as you type — no button needed.
  2. Toggle URL-safe mode if the result will go into a URL, file name or JWT-style token: + and / become - and _.
  3. Copy the output with one click. The status line shows the input size in bytes versus the output length.
  4. Decode it back any time with the Base64 Decoder — the round trip is lossless.

Useful information

Base64 represents binary data using 64 printable characters — A–Z, a–z, 0–9, + and /. Every 3 input bytes become 4 output characters, which is why encoded text is about a third longer than the original.

How encoding works here

Your text is first converted to UTF-8 bytes (so emoji and non-Latin scripts are handled properly), then those bytes are base64-encoded. Naive implementations that call btoa() directly crash on anything outside Latin-1 — this tool doesn't.

Standard vs URL-safe

Standard Base64 produces + and /, both of which are meaningful (and problematic) inside URLs. URL-safe mode replaces them with - and _, the alphabet used by JWTs, S3-style keys and most modern APIs.

Encoding is not encryption

This is worth repeating: Base64 is reversible by anyone in a single step. It's useful for embedding binary in text formats, sending data through systems that only handle ASCII, or avoiding URL mangling — it offers zero confidentiality. For real protection, use proper encryption.

Frequently asked questions

How do I encode text to Base64?

Paste or type your text and the Base64 output appears instantly — or press Encode if you've just changed options. Use the Copy button to grab the result.

What is URL-safe Base64?

Standard Base64 uses + and /, which break in URLs and file names. URL-safe mode swaps them for - and _, so the output can sit in a path or query string unchanged.

Does Base64 hide or encrypt my data?

No. Base64 is an encoding, not encryption — anyone can decode it in one step. Never use it to protect passwords, keys or private information.

Does it handle emoji and other languages?

Yes. Text is converted to UTF-8 bytes before encoding, so emoji, Hindi, Arabic or any Unicode content round-trips correctly through the matching decoder.

Is my text stored anywhere?

No. Encoding happens entirely in your browser — your text is never sent to a server or saved by Jivora.
